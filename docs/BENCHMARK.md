# Benchmark And Dataset Validation Report

This report records measured validation results for the current Financial Knowledge Intelligence Platform and provides the reproducible workflow for a larger SEC EDGAR validation run targeting approximately 500 public 10-K/10-Q filings.

No performance numbers are estimated. The 500-document SEC collection was not completed in this environment because it requires a real SEC User-Agent/contact identity and a longer network/download run. The measured results below come from a small end-to-end smoke benchmark using the existing sample financial documents with PostgreSQL and Qdrant wired through Docker Compose.

## Methodology

The smoke benchmark validated the existing production-style path:

1. Start PostgreSQL, Qdrant and Alembic migration service through Docker Compose.
2. Ingest the sample financial manifest through the existing CLI inside the API container.
3. Persist metadata to PostgreSQL.
4. Store extracted raw text with `LocalObjectStorage`.
5. Index document and chunk vectors in Qdrant.
6. Rebuild the vector index to measure chunk indexing separately.
7. Run a retrieval query against Qdrant.
8. Generate a cited extractive RAG answer.
9. Run the existing local benchmark helper separately to record its SQLite/LocalVectorStore baseline.

The local benchmark helper intentionally uses temporary SQLite and `LocalVectorStore`, so its numbers are not comparable with the PostgreSQL/Qdrant smoke path.

## Meaningful Failure Categories Observed

The benchmark process found one real production-path bug:

- Failure: reindexing PostgreSQL documents into Qdrant failed because PostgreSQL returned UUID values as UUID objects, which the Qdrant JSON request serializer could not encode.
- Fix applied: `PostgresMetadataRepository` row conversion now normalises `document_id` to `str`.
- Regression test added: `tests/test_metadata_repository.py`.
- Verification after fix: unit tests passed, compile checks passed and Qdrant reindex/search/RAG smoke validation passed.

Environment issues observed:

- Host Python did not have `psycopg` installed, so PostgreSQL validation was run inside the existing Docker API container where project dependencies are installed.
- Local network access to Qdrant was restricted by the execution sandbox, so Docker-based validation was run with approved local Docker/network access.

## Reproducible 500-Filing SEC Workflow

Set a real SEC-compliant User-Agent before collection:

```bash
export SEC_USER_AGENT="Your Name your.email@example.com"
```

### 1. SEC Collection And Manifest Generation

```bash

  --user-agent "$SEC_USER_AGENT" \
  --tickers-file config/sec_tickers_large_cap.txt \
  --forms 10-K,10-Q \
  --max-documents 500 \
  --per-company-limit 6 \
  --request-delay-seconds 0.2 \
  --output-root data/raw/sec \
  --manifest-output data/manifests/sec_financial_documents.json \
```

## Limitations

- The measured smoke dataset is intentionally tiny and should not be used to claim 500-document performance.
- The SEC 500-document workflow was prepared but not executed in this environment.
- SEC collection depends on network availability and SEC fair-access policies.
- The collector requires a real User-Agent with contact information.
- Current ingestion is synchronous; larger runs may require queue-backed workers in a real production deployment.
- Raw text storage still uses `LocalObjectStorage`; MinIO is present as a future deployment option but is not the active adapter.
- The default embedding model is deterministic and local, which is useful for reproducibility but not a production-grade financial embedding model.

## Lessons Learned

- The current architecture is measurable: ingestion metrics, dataset statistics, reindex counts and retrieval latency can be captured without adding new product features.
- The PostgreSQL and Qdrant path is useful because it exposed a UUID serialization issue that local SQLite tests did not catch.
- Keeping `LocalVectorStore` is still valuable for fast tests, but production-path smoke tests are necessary for adapter compatibility.
- For interview use, present the measured smoke results separately from the prepared 500-filing workflow. Do not claim full SEC-scale performance until the SEC collection and ingestion commands have been run locally end to end.
